## Phase 1 — Audit

- **Framework:** Plain static HTML (no build step, no SSR/SSG, no client-side framework).
  This is actually a *good* thing for crawlability — there's no JS-rendering gap for crawlers
  or AI bots to fall into.
- **robots.txt:** Present, allows all crawlers (`User-agent: * / Allow: /`), correctly does
  not block GPTBot, ClaudeBot, PerplexityBot, or Google-Extended. Points to the sitemap. Good.
- **sitemap.xml:** Present, wired up, lists all 19 real pages with plausible priorities/changefreq.
  No dead or orphaned entries found. Good.
- **Title tags:** Present and unique on all 19 pages, `TRASIER | ...` pattern, all under
  60 characters. Good.
- **Meta descriptions:** Present and unique on all 19 pages, but **5 pages ran 161-204
  characters** — past the ~155-160 char point where Google truncates the SERP snippet
  mid-sentence: `index.html` (204), `sadak-sujhav.html` (191), `company.html` (186),
  `case-study-sadak-sujhav.html` (161), `blog/2026-09-14-site-and-product-updates.html` (183).
  **Fixed this run — see PR #1.**
- **Headings:** Exactly one `<h1>` per page across all 19 pages. Good.
- **Image alt text:** Every `<img>` tag on the site has an `alt` attribute. Good.
- **Canonical tags:** Present and correct (self-referencing, absolute URL) on every page. Good.
- **Open Graph / Twitter cards:** Present and complete on every page. Good.
- **Structured data (JSON-LD):** Present on `index.html` and `company.html` (`Organization`)
  and `sadak-sujhav.html` / `case-study-sadak-sujhav.html` (`SoftwareApplication`). **Missing
  entirely on all 6 `services/*.html` pages** and on the secondary pages (careers, contact,
  leadership, blog, legal pages). **Added Service schema to the 6 service pages this run —
  see PR #2.** Left the secondary/legal pages without schema for now — lower priority, revisit
  if service-page schema shows an effect.
- **No `noindex` tags** anywhere on the site (checked all 19 pages) — nothing is accidentally
  blocking indexing at the page level.
- **`/llms.txt`:** Does not exist. Low-priority per the skill's own guidance — noting it,
  not opening a PR for it this run.
- **Broken links:** Checked every internal `href` across all pages against the actual file
  tree — all resolve. No broken internal links found.
- **Content depth:** Homepage ~1,230 words, Sadak Sujhav ~825, company ~755, case study
  ~1,010 — reasonable depth, not thin. Blog has only 1 post (launched today) — expected for
  a brand-new blog, but worth a content-cadence push (see Ongoing, below).

## Phase 2 — Research

No Search Console data available this run (see environment note above), so this is web
research only.

- **Brand/product visibility is currently at zero.** Web searches for `"Trasier Technology"`,
  `"Sadak Sujhav"`, `site:trasiertech.com.np`, and `"trasiertech.com.np"` returned **no
  results referencing the company, its product, or its domain at all** — not even the
  homepage itself. This is the single most important finding from this run: on-page fixes
  don't matter yet if the site isn't showing up in the index at all. Given the site has
  existed since ~June 2026 with regular commits, this points to an indexing/authority gap
  rather than a brand-new-site timing issue alone.
- **No external entity signals found.** No LinkedIn company page, no GitHub org, no
  Twitter/X, Facebook, or Instagram presence turned up in search, and the site itself links
  to none of these (checked every page's footer/nav for social links — none exist). Combined
  with zero backlinks, this likely explains a lot of the indexing gap above: there's nothing
  pointing at the site from anywhere else on the web yet.
- **Generic query competitors** (for `"software company Kathmandu Nepal government projects"`,
  `"civic software Nepal government complaint management system"`): the official government
  portal **Hello Sarkar / Gunaso** (gunaso.opmcm.gov.np) dominates the civic-complaint space;
  established local software firms like Softech Infosys, Neuro AI Nepal, SoftNEP, and
  Professional Computer System show up for the general "software company Nepal" queries.
  None of these are direct product competitors to Sadak Sujhav specifically, but they occupy
  the search real estate Trasier Technology wants to eventually share.
- Search Console is noted as a recommendation to reconnect (`GSC_SERVICE_ACCOUNT_JSON`
  secret) — once live, it will show actual impressions/indexing status instead of this
  external-search-only approximation.

## Phase 3 — Recommendations

**Fix now**
1. Trim the 5 over-length meta descriptions to ~150-160 chars. *(Quick — done, PR #1)*

**This month**
2. Add `Service` structured data to the 6 service pages so search/AI engines have an
   explicit description of each offering tied back to the Organization entity.
   *(Medium — done, PR #2)*
3. Create a Trasier Technology LinkedIn company page and a public GitHub org/profile, and
   link them from the site footer + the `Organization` JSON-LD `sameAs` field once they
   exist. This is the highest-leverage open item given the zero-backlink finding above, but
   it requires the client to actually create the profiles first — not something this agent
   can do from the repo. *(Medium, blocked on the client)*
4. Confirm the sitemap has actually been submitted inside Search Console and check the
   Coverage report for indexing errors once GSC access is restored. *(Quick, blocked on
   GSC access)*

**Ongoing**
5. Backlink/citation building: local Nepal business directories, a Product Hunt or dev
   community post for Sadak Sujhav, press coverage of the municipal pilot if any exists.
   Zero backlinks is the biggest structural gap found this run.
6. Blog cadence: 1 post is a fine start; a regular publishing rhythm (even monthly) gives
   crawlers a reason to revisit and builds the freshness/depth signal the site currently lacks.
7. Add `/llms.txt` at some point — low priority, doesn't block anything, cheap to do
   whenever there's a spare cycle.
