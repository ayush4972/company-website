## Pattern notes

1. **The PR-review bottleneck is cyclical, not solved.** The 2026-09-28/2026-10-05 backlog (five
   PRs, up to three weeks old) cleared in one batch on 2026-10-11, but two new PRs from the very
   next run (#10, #11) have already sat a week with no review. Worth watching whether this
   settles into a "reviewed roughly every 1-2 weeks" rhythm (which would still work fine for
   this loop) or re-grows into another multi-week pile.
2. **Search visibility has now been zero for six consecutive runs**, spanning two full months of
   on-page work that's been clean for five of those six. Every working theory from prior runs
   (new-site timing, missing backlinks, press not crediting the brand, no GSC ground truth) is
   still live and none has been confirmed or ruled out, because the one data source that would
   settle it — Search Console — has never been available in any run's environment. This is the
   single most important thing a future run (or a human) could unblock: it would turn six runs
   of "still zero, still unmeasured" into an actual diagnosis.
3. **Over-length titles/descriptions keep showing up on new blog posts specifically, not on the
   stable pages.** Every title/description-length finding across all six runs (PR #1, #4, #10,
   #12) has been on a page added or edited outside this agent's own PRs — the site's static
   pages have stayed clean once fixed once. A short title/description length check added to
   whatever process the site maintainer uses when drafting a new post (or a simple character-
   count lint in CI) would catch this before it reaches a PR at all; flagging as a process idea,
   not something this run is acting on unilaterally.
